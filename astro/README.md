# donttalk — Portfolio Site (Astro Frontend)

Static multi-page portfolio site for [donttalk.vercel.app](https://donttalk.vercel.app).

Built with [Astro 6](https://astro.build). Deployed to Vercel via `vercel.json` at the repo root (not in this subdirectory).

---

## What's in here

- **24 pages** under `src/pages/` — work portfolio, blog, music player, two games
- **`public/styles/` and `public/scripts/`** — page-specific CSS / JS, one pair per page
- **`src/layouts/Base.astro`** — shared layout (head, nav, footer, theme, service worker, search modal)
- **`src/content/blog/`** — Astro content collections for blog posts
- **`public/music/playlist.json`** + 65 mp3 tracks — music player data
- **`public/games/xian/`** — vanilla JS side-scroller
- **`public/games/xian-godot/`** — Godot 4 source (built separately, not part of Astro build)

Page templates use a simple pattern: `import Base from '../layouts/Base.astro'` + a `<Base>` wrapper. Most pages pass `pageStyles={[…]}` and `pageScripts={[…]}` to load their specific CSS/JS.

## Commands

Run from this directory (`astro/`):

| Command | What it does |
| :-- | :-- |
| `npm install` | Install dependencies (uses `engines: node >=22.12.0`) |
| `npm run dev` | Dev server at `http://localhost:4321` |
| `npm run build` | Build to `dist/`, then run Pagefind to build the search index into `dist/pagefind/` |
| `npm run preview` | Preview the built `dist/` locally |
| `npm run astro -- --check` | TypeScript / Astro diagnostics |

`npm run build` is what Vercel runs in CI (see root `vercel.json` → `buildCommand`).

## Adding a new page

1. Create `src/pages/your-page.astro`:
   ```astro
   ---
   import Base from '../layouts/Base.astro';
   ---
   <Base
     title="..."
     description="..."
     bodyPage="your-page"
     pageStyles={["/styles/your-page.css"]}
     pageScripts={["/scripts/your-page.js"]}
   >
     <!-- your HTML -->
   </Base>
   ```
2. If your page needs its own styles, add `public/styles/your-page.css`.
3. If your page needs JS, add `public/scripts/your-page.js`. **Don't** add a second `<script src="...">` at the end of the body — `Base.astro` already loads files from `pageScripts`.
4. `npm run dev` to preview, then `npm run build` to verify the production bundle.

The music page (`src/pages/music.astro`) is the canonical example of the right shape after the 2026-06-03 refactor.

## Caching

The root `vercel.json` sets these cache headers:

| Path | Header | Why |
| :-- | :-- | :-- |
| `/_astro/*` | `max-age=31536000, immutable` | Astro hashes the filename on content change |
| `/videos/*` | `max-age=31536000, immutable` | Videos are content-addressed by URL |
| `/scripts/*`, `/styles/*` | `max-age=0, must-revalidate` | **No hash in filename** — long cache would break deploys. Browsers send `If-None-Match` on every visit; Vercel returns 304 in <50ms when unchanged |
| `/music/*` | `max-age=0, must-revalidate` | Same reasoning — HTML changes more often than JS/CSS |

If you ever want to add long cache to `public/scripts/*`, you must rename the files with content hashes (e.g. `music-player.v1.js`) — see the Vite / Astro docs on hashed assets.

## Deployment

Pushing to `main` triggers a Vercel production build. See the **Deployment** section in the repo root README (or `vercel.json` if no root README) for the GitHub → Vercel connection details.

Build flow on Vercel:
1. `cd astro && npm ci`
2. `cd astro && npm run build` (Astro build + Pagefind indexing)
3. Deploy `astro/dist/` to the `donttalk.vercel.app` domain

If a deploy doesn't seem to pick up changes, check:
- Vercel Dashboard → Deployments → latest commit hash matches what you pushed
- `X-Vercel-Cache: HIT/MISS` on `curl -I` to confirm the CDN edge is seeing the new build

## Backend integration (optional)

Some pages (`gene-ai`, `ngs`, `interview`) call a FastAPI service at `https://donttalk-api-production.up.railway.app` via the rewrites in the root `vercel.json`:

```
/api/:path* → https://donttalk-api-production.up.railway.app/api/:path*
```

The FastAPI source lives in the repo root (`api/`, `site_api/`). The Astro site itself works as a pure static site — if the API is down, pages render their empty/loading state but don't break.

## Gotchas (lessons learned)

- **Don't** create `astro/vercel.json` — it overrides the root `vercel.json` for the entire project (Vercel merges per-directory). The root one is the single source of truth.
- **Don't** add `<script src="scripts/foo.js">` at the end of a `bodyHtml` JS string in a `.astro` page — `Base.astro` already loads it via `pageScripts`. Adding it again makes the browser fetch and execute the script twice.
- **Don't** add a long `Cache-Control: max-age=31536000, immutable` header to `/scripts/*` or `/styles/*` — those filenames have no content hash. A user who visited once will be stuck on that version for a year.
- **Vercel's "Connect Git Repository"** in project settings is **per project**. If push isn't triggering builds, the project is not connected to the GitHub repo — fix it under Settings → Git, then push again to trigger.
