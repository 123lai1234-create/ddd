/**
 * A0006 使用者角色管理 Controller
 *
 * 
提供「使用者帳號」與「角色代碼」之間的指派維護作業 REST 介面,
 * 對應前端的「角色權限管理」畫面。

 *
 * 
五大介面:
 * 
    
 *   
  • GET    /api/A0006/options  - 取得角色選項
    • 
 *   
  • GET    /api/A0006/userRole - 查詢使用者(含角色)
    • 
 *   
  • PATCH  /api/A0006/userRole - 修改使用者與角色
    • 
 *   
  • DELETE /api/A0006/userRole - 刪除使用者與角色
    • 
 *   
  • POST   /api/A0006/userRole - 新增使用者與角色
    • 
 * 

 * 

 */
@RestController                                    // ⓐ 詳見下方說明
@RequestMapping("/api/A0006")                      // ⓑ 詳見下方說明
public class A0006Controller {

    private final A0006Service a0006Service;

    // ========== 介面 1: GET /api/A0006/options ==========
    @GetMapping("/options")                        // ⓒ 詳見下方說明
    public ResponseEntity getOptions() {
        A0006OptionsResponse response = a0006Service.getOptions();
        return ResponseEntity.ok(response);
    }

    // ========== 介面 2: GET /api/A0006/userRole ==========
    @GetMapping("/userRole")                       // ⓒ 詳見下方說明
    public ResponseEntity> queryUserRole(
            @RequestParam(name = "userId", required = false) String userId,        // ⓓ
            @RequestParam(name = "isEnabled", required = false) Integer isEnabled  // ⓓ
    ) {
        List result = a0006Service.queryUserRole(userId, isEnabled);
        return ResponseEntity.ok(result);
    }

    // ========== 介面 3: PATCH /api/A0006/userRole ==========
    @PatchMapping("/userRole")                      // ⓔ 詳見下方說明
    public ResponseEntity updateUserRole(
            @Valid @RequestBody A0006UpdateRequest request                          // ⓕ ⓖ
    ) {
        String operator = "admin";
        ApiResponse response = a0006Service.updateUserRole(request, operator);
        return response.getResponseCode() == 200
                ? ResponseEntity.ok(response)
                : ResponseEntity.badRequest().body(response);
    }

    // ========== 介面 4: DELETE /api/A0006/userRole ==========
    @DeleteMapping("/userRole")                     // ⓗ 詳見下方說明
    public ResponseEntity deleteUserRole(@Valid @RequestBody A0006DeleteRequest request) {
        ApiResponse response = a0006Service.deleteUserRole(request);
        return response.getResponseCode() == 200
                ? ResponseEntity.ok(response)
                : ResponseEntity.badRequest().body(response);
    }

    // ========== 介面 5: POST /api/A0006/userRole ==========
    @PostMapping("/userRole")                       // ⓘ 詳見下方說明
    public ResponseEntity createUserRole(@Valid @RequestBody A0006CreateRequest request) {
        String operator = "admin";
        ApiResponse response = a0006Service.createUserRole(request, operator);
        return response.getResponseCode() == 200
                ? ResponseEntity.ok(response)
                : ResponseEntity.badRequest().body(response);
    }
}

📖 Annotation 詳細說明

ⓐ @RestController Spring Web · 類別層級
用途宣告此類別為 REST 風格的 Controller,等同於同時加上 @Controller + @ResponseBody。
效果方法回傳值會透過 HttpMessageConverter(預設為 Jackson)直接序列化為 JSON / XML,不再走 ViewResolver(不會解析 JSP / Thymeleaf)。
套件org.springframework.web.bind.annotation.RestController
範例
@RestController
public class A0006Controller { ... }
ⓑ @RequestMapping Spring Web · 類別/方法層級
用途設定 URL 路徑 與 HTTP 方法 的對應。可加在類別(共同前綴)或方法(個別端點)上。
效果類別層級:此 Controller 內所有端點都會繼承此路徑前綴。
方法層級:可省略 method 屬性,改用具名註解(如 @GetMapping)。
常用屬性 value / path — URL 路徑
method — HTTP 方法(GET/POST/PUT/DELETE/PATCH)
produces — 設定 response 的 Content-Type
consumes — 限制 request 的 Content-Type
套件org.springframework.web.bind.annotation.RequestMapping
範例
@RequestMapping("/api/A0006") // 共同前綴
public class A0006Controller { ... }
ⓒ @GetMapping Spring Web · 方法層級 · HTTP GET
用途將 HTTP GET 請求綁定到此方法。語意上等同於 @RequestMapping(method = RequestMethod.GET)。
效果僅接受 GET 請求。GET 為安全(safe)且冪等(idempotent),適合查詢、不改變伺服器狀態、可被快取。
屬性 value / path — 子路徑;完整路徑 = 類別前綴 + 此屬性
params — 限制 query 必須包含特定參數
headers — 限制 request header
套件org.springframework.web.bind.annotation.GetMapping
本檔使用
@GetMapping("/options") → GET /api/A0006/options
@GetMapping("/userRole") → GET /api/A0006/userRole
ⓓ @RequestParam Spring Web · 參數層級
用途將 URL Query String(或 form data)中的參數綁定到方法參數。
效果Spring 在呼叫方法前,會從 request 中取出對應名稱的參數值,自動做型別轉換(字串 → Integer / Boolean 等)。
常用屬性 name / value — 對應 query 參數名稱
required — 是否必填(預設 true);false 時省略則為 null
defaultValue — 預設值(required=false 時常用)
套件org.springframework.web.bind.annotation.RequestParam
本檔範例
GET /api/A0006/userRole?userId=admin&isEnabled=1

@RequestParam(name = "userId", required = false) String userId
@RequestParam(name = "isEnabled", required = false) Integer isEnabled
ⓔ @PatchMapping Spring Web · 方法層級 · HTTP PATCH
用途綁定 HTTP PATCH 請求,語意為「部分更新」。
效果PATCH 與 PUT 的差異:PUT 是「整體取代」,PATCH 是「只更新部分欄位」。本介面用 PATCH 表示只更新部分使用者欄位。
屬性 value / path — 子路徑;完整路徑 = 類別前綴 + 此屬性 = /api/A0006/userRole
套件org.springframework.web.bind.annotation.PatchMapping
本檔範例
@PatchMapping("/userRole") → PATCH /api/A0006/userRole
ⓕ @Valid Bean Validation · 參數層級
用途觸發 Bean Validation(Jakarta Validation),對方法參數(或物件內的欄位)進行約束條件驗證。
效果在進入方法本體前,先依 DTO 內的 @NotBlank / @Email / @Size / @Pattern 等約束檢查欄位。
失敗處理驗證失敗時拋出 MethodArgumentNotValidException(或 ConstraintViolationException),通常由 @ControllerAdvice + @ExceptionHandler 統一接住。
套件jakarta.validation.Valid
範例
public class A0006UpdateRequest {

  @Email  private String userEmail;
}

public ResponseEntity update(@Valid @RequestBody A0006UpdateRequest req) { ... }
ⓖ @RequestBody Spring Web · 參數層級
用途將 HTTP 請求主體(Body)反序列化為 Java 物件(預設讀取 JSON)。
效果透過 HttpMessageConverter(Spring Boot 內建 Jackson)自動將 JSON 字串轉成對應的 DTO。搭配 @Valid 會在反序列化後做欄位驗證。
常用屬性 required — Body 是否必填(預設 true)
consumes — 限制 Content-Type(例如 application/json)
套件org.springframework.web.bind.annotation.RequestBody

ⓗ @DeleteMapping Spring Web · 方法層級 · HTTP DELETE
用途綁定 HTTP DELETE 請求,語意為「刪除資源」。
效果HTTP 規範上 DELETE 應為 冪等(Idempotent):重複呼叫結果應一致(都是「已刪除」)。
注意嚴格 REST 會將識別值放在 Path(如 /users/{id}),本介面實作為透過 @RequestBody 傳遞 userId。
套件org.springframework.web.bind.annotation.DeleteMapping
本檔範例

ⓘ @PostMapping Spring Web · 方法層級 · HTTP POST
用途綁定 HTTP POST 請求,語意為「新增資源」或「觸發動作」。
效果POST 屬於 非冪等(Non-idempotent):重複呼叫會建立多筆資料。若需冪等(避免重複新增),請改用 PUT 或加入唯一性檢查。
屬性 value / path — 子路徑
consumes — 限制 Content-Type
produces — 設定 response 的 Content-Type
套件org.springframework.web.bind.annotation.PostMapping
本檔範例
@PostMapping("/userRole") → POST /api/A0006/userRole
ⓙ @Service Spring Stereotype · 類別層級
用途把此類別註冊為 Spring IoC 容器中的「服務層 Bean」。
效果啟動時 Spring 會透過 @ComponentScan 掃描並自動建立實例,供 @Autowired / 建構子注入使用。
Stereotype 比較

ⓚ @Qualifier Spring DI · 參數層級
用途當容器中 同一型別有多個 Bean 時,用「Bean 名稱」明確指定要注入哪一個。
使用情境專案內可能同時存在多個 JdbcTemplate(如 primaryJdbcTemplate、sitJdbcTemplate、uatJdbcTemplate...),僅靠型別無法決定注入哪個,需搭配 @Qualifier。
套件org.springframework.beans.factory.annotation.Qualifier

ⓛ @Transactional Spring Transaction · 方法/類別層級
用途宣告此方法(或整個類別)需在 資料庫交易(Transaction) 內執行。
效果 方法開始時自動開啟交易;
正常返回時 commit;
拋出 RuntimeException(未捕捉)時 自動 rollback;
拋出 Checked Exception 時不會自動 rollback(需透過 rollbackFor 設定)。
常用屬性 rollbackFor — 指定哪些例外要觸發 rollback(如 Exception.class 涵蓋所有)
noRollbackFor — 指定哪些例外不要 rollback
propagation — 交易傳播行為,預設 REQUIRED(沿用或新開)
isolation — 交易隔離等級(如 READ_COMMITTED)
timeout — 交易逾時秒數
readOnly — 是否為唯讀交易(可提升效能)
套件org.springframework.transaction.annotation.Transactional
本檔使用套用於 updateUserRole、deleteUserRole、createUserRole,確保多步驟寫入的一致性。
範例
@Transactional
public ApiResponse createUserRole(A0006CreateRequest req, String operator) {
  // 任一步驟失敗,前面已執行的 DB 操作都會 rollback
  sysUserRepository.save(user);
  replaceRoles(userId, req.roles(), operator);
}

🔒 A0006Service 內部方法(private)

replaceRoles(String userId, List roles, String actor)
替換指定使用者的角色(先刪後增),給 create / update 共用
  • sysUserRoleRepository.deleteByUserId(userId) → 先刪除舊角色關聯
  • hasText(role.roleCode()) → 過濾空白角色代碼(避免寫入空字串)
  • new SysUserRole() → 建立角色關聯實體(含 createEmp/updateEmp)
  • sysUserRoleRepository.saveAll(rows) → 批次寫入新角色(單一交易)
groupRoles(Collection rows)
將角色清單依 userId 分組為 LinkedHashMap(保留插入順序)
  • map.computeIfAbsent(r.getUserId(), k -> new ArrayList<>()).add(r)
  • 回傳 Map>,key = userId、value = 該使用者的所有角色
requireCrypto()
從 ObjectProvider 取得 AES 加密器,若未設定則拋出例外(fail-fast)
  • cryptoProvider.getIfAvailable() → 嘗試取得 Bean;可能為 null
  • throw new IllegalStateException("AES key not configured...") → 明確告知缺失的金鑰設定
loadMsRoleDescMap()
載入 MS 角色別對照表(cossdb.dbo.CDLEVEL,SysId='MS')
  • jdbcTemplate.queryForList(sql) → 查詢 CDLevel / LevelDesc
  • TextEncodingFixer.repairUtf8MojibakeIfLikely(roleDesc) → 修復亂碼
  • String.valueOf(codeObj) / String.valueOf(descObj) → 轉字串(防 NPE)
  • map.put(roleCode, roleDesc) → 組裝 LinkedHashMap(保留 DB 順序)
  • 例外時 throw new IllegalStateException("無法查詢 cossdb.dbo.CDLEVEL...")
normalizeEnabledBool(Integer isEnabled)
將 Integer (0/1) 轉為 Boolean;null 維持 null(給查詢條件用)
  • return isEnabled == null ? null : isEnabled != 0; // 0 → false;非 0 → true
normalizeNullableString(String value)
去除前後空白;若為空字串則回傳 null(避免空白誤判為有效值)
  • return trimmed.isBlank() ? null : trimmed;
hasText(String value)
檢查字串是否非 null 且 trim 後不為空(必填欄位驗證)
  • return value != null && !value.trim().isBlank();
normalizeActor(String actor)
標準化操作人員名稱;空白時預設為 "system"(避免 NULL 寫入稽核欄位)
  • return normalized.isBlank() ? "system" : normalized;
