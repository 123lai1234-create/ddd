Cortex-M0 Nano130KE3BN Keil µVision J-Link EBI / SPI / I2C RGB565

🎯 代表作：TFT 圖片顯示驅動

在 Nuvoton Nano130KE3BN 開發板上，透過外部匯流排介面（EBI）驅動 TFT 面板輸出 RGB565 圖片。重點是在只有 16 KB SRAM / 128 KB Flash 的 Cortex-M0 上，對記憶體預算做精細規劃，把高解析度點陣圖直接鎖進 Flash，零 SRAM 執行時配置。

記憶體預算推導

// Flash 佔用 (bytes) flash_usage = width × height × 2 // RGB565 = 2 B/px // 以 200 × 220 為例 flash_usage = 200 × 220 × 2 = 88000 B ≈ 86 KB // Nano130 Flash 上限 128 KB → 扣掉程式碼 ~30 KB → 剩 ~98 KB // 一張大圖吃掉整個 Flash 圖片預算，需要先壓縮或分頁載入

從 PNG 到 C array 的轉換流程

  1. 輸入 PNG / JPG（< 300 KB）透過 Rinky-Dink Electronics 影像轉換器 轉成 RGB565
  2. 輸出 const unsigned short img2[N] = { ... } C header
  3. 放進 Keil project 的 img2.c，以 const 讓編譯器鎖在 Flash（非 SRAM）
  4. 透過 EBI 位址寫到 TFT 控制器，DMA-less 但 CPU 週期可控
  5. J-Link 下載後實機驗證波形與畫面

示例：Flash-resident 影像宣告

/* img2.c — 200x220 RGB565, Flash-resident */ const unsigned short img2[44000] = { 0x0000, 0x0000, 0x1082, 0x2965, 0x41A7, /* ... ~44 K entries, each 16-bit RGB565 pixel ... */ }; /* main.c — EBI blit loop */ void tft_blit(const uint16_t *buf, uint32_t n) { for (uint32_t i = 0; i < n; i++) { EBI_WRITE_DATA(buf[i]); // memory-mapped I/O } }

技術難點 & 處理

  • Flash 空間爆表 → 降採樣至 200×220，犧牲解析度換 Flash；或改用 SPI Flash 外掛儲存
  • EBI 時序對齊 → 調整 tAS / tAH 匹配 TFT 控制器 setup/hold；用邏輯分析儀驗證波形
  • Keil licensing → 免費版有 32 KB 上限，需申請 PSN 註冊碼才能編譯完整 image
