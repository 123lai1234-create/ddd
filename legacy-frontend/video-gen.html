架構深度說明

Submit / Poll 非同步設計

生成任務通常需要 30–120 秒，遠超 HTTP timeout。FastAPI 代理採 submit-then-poll 模式，讓前端持續輪詢而不阻塞連線。

01
前端送出 Prompt
使用者在頁面填入 prompt、選擇解析度與時長，前端 POST 到 Railway FastAPI（不含 API key）。
02
FastAPI 驗證 + 限速
後端驗證 prompt 長度、IP 頻率限制（3 次/IP/天），通過後以 FAL_KEY 呼叫 fal.ai submit endpoint。
03
fal.ai 非同步排隊
fal.ai 接收請求後立即回傳 request_id，將任務排入 Seedance 2.0 推理佇列，FastAPI 回傳此 ID 給前端。
04
前端輪詢狀態
前端每 5 秒以 request_id 查詢 FastAPI status endpoint，後端轉發至 fal.ai 取得 IN_QUEUE / IN_PROGRESS / COMPLETED。
05
取得影片 URL 並播放
狀態為 COMPLETED 後，後端回傳 fal.ai CDN 影片 URL，前端直接以 <video> 播放，API key 全程不離開後端。

為什麼要用 FastAPI 當 proxy？
API key 放後端環境變數，前端只拿到 request_id 和影片 URL，避免 key 暴露在 JavaScript 原始碼中被爬取。
為什麼不同步等待回應？
生成時間 30–120 秒，Railway 的 HTTP timeout 遠小於此。非同步 submit/poll 讓連線立即返回，前端自行追蹤進度。
為什麼選 fal.ai？
fal.ai 提供標準化的佇列 API（submit + status + result），免去自建 GPU 推理基礎設施，且支援 Seedance 2.0 等前沿模型。
影片生成有哪些限制？
每 IP 每天 3 次，prompt 限 3–500 字元，建議英文。1080p 生成時間較長（可達 2 分鐘），且受 fal.ai 佇列負載影響。
